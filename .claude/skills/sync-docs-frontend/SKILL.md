# /sync-docs

Reconcile this repo's documentation with the code. The canonical docs live in the **`b2b-reservas-frontend` skill** — `.claude/skills/b2b-reservas-frontend/references/*.md` (detail) and `.claude/skills/b2b-reservas-frontend/SKILL.md` (entry point) — plus `CLAUDE.md` (thin pointer). They are the company reference standard — keep them true, conservative, and consistent.

> **Path note.** All `*.md` doc targets below live under `.claude/skills/b2b-reservas-frontend/references/`.

## Scope (pick from the argument)

| Invocation | What to reconcile |
|---|---|
| `/sync-docs` | The working-tree delta — `git status --porcelain` (staged + unstaged + untracked). Matches the Stop hook. |
| `/sync-docs <path>` | Only the area you point at (e.g. `src/components/users`). |
| `/sync-docs all` | Full audit: whole codebase vs every doc. |

## Procedure

1. **Resolve scope** → list the changed (or targeted) files. For default scope: `git status --porcelain`. For `all`: walk `src/`, `public/`, `docker/`, `infra/`, and root config.
2. **Map** each changed area to its owning doc (table below).
3. **Read** the owning doc(s). Compare documented behavior, commands, code samples, folder structure examples, and stack against the actual code.
4. **Draft + apply** the minimal edits that make the doc true again. Match the doc's existing tone and structure; do not rewrite wholesale.
5. **Report**: list what was applied and what is proposed-pending-approval.

## Autonomy rules

**Auto-apply (no prompt):**
- Edits to existing `references/*.md` prose, code samples, tables.
- Fixes to commands in `CLAUDE.md` §4 and `SKILL.md` §6.
- Folder-tree examples in `SKILL.md` §4 and `ARCHITECTURE.md` §2 when a new `src/components/<modulo>/`, `src/hooks/<modulo>/`, or `src/schemas/<modulo>/` is created.
- Updates to `public/locales/<lng>/<modulo>.json` mentions when a new locale namespace is added.

**ASK first (propose, wait for approval):**
- Creating a **new** `references/*.md` file.
- Adding a `SKILL.md` §5 index entry (always paired with a new reference).
- Changing the `SKILL.md` §2 stack table (lib swap or version bump that changes the recommendation).
- Removing or renaming an existing reference.
- Touching `DECISIONS.md` to add an ADR.

A new reference is warranted only for a genuinely new subsystem or cross-cutting concern with no existing home. Default to extending an existing reference.

## Module-aware behavior

When `<path>` is a module folder (`src/components/users`, `src/hooks/users`, `src/schemas/users`):

1. Cross-check the **three** module slices — components, hooks, schemas — even if only one was touched. Common drifts:
   - Added `src/components/users/user-form.tsx` but no `src/schemas/users/create-user.schema.ts`.
   - Added hook `use-delete-user.ts` but didn't reference it from any component example in docs.
2. Update `ARCHITECTURE.md` § "Anatomia de um módulo" if the module structure exemplifies a new pattern.
3. If the module touches API endpoints, verify `src/lib/api/modules/<modulo>.ts` exists with `<MODULO>.ENDPOINT`. If missing, propose creation.

## Common mistakes

- Editing a doc the change does not actually affect — only touch mapped, verified gaps.
- Rewriting a whole reference when a targeted edit suffices.
- Auto-creating a new reference or editing the stack table without asking.
- Leaving `SKILL.md` §5 index stale after a new reference is approved.
- Forgetting to update folder-tree examples in `SKILL.md` §4 when a new module is added.
- Updating `PERMISSIONS.md` examples to use a string literal (`"HOTEL_ADMIN"`) instead of catalog variable (`PERMISSIONS.HOSPITALITY.HOTEL_ADMIN`) — the catalog-only rule is non-negotiable.
- Reporting "docs updated" without naming which files and what changed.
